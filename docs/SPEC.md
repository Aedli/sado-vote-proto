# 세계수 교단 수석 사도 투표 — 플레이어블 프로토타입 개발 명세서

> 이 문서는 프로토타입 구현의 **단일 기준 문서(Source of Truth)**다.
> 원본 콘텐츠 기획서: `docs/09_트릭컬_콘텐츠창작서_수석사도투표.pdf`
> 규칙 수치가 이 문서와 기획서 사이에서 다를 경우 **이 문서를 따르고**, 애매한 부분은 구현 전에 기획자에게 질문한다.

---

## 0. 목적

1. **구현** — 기획서의 규칙(예선·본선·보상)과 화면 연출 흐름이 실제로 작동하는 것을 보여준다. 플레이어는 교주 한 명으로 2주 이벤트를 수 분 안에 압축 체험한다.
2. **검증** — 플레이어와 동시에 같은 규칙으로 움직이는 가상 유저(봇) 수천 명을 시뮬레이션해, 기획 의도가 실제로 달성되는지 수치로 확인한다.
3. **비교** — 기획자 패널에서 규칙·가정값을 바꿔 여러 시나리오를 돌리고 결과를 비교한다.

### 범위 밖 (구현하지 않음)
- 실제 전투 시스템(차원 대충돌). 딜량은 **공식으로 추상화**한다(§5).
- 실제 일일 퀘스트 콘텐츠. 미션은 **버튼으로 완료 처리**한다.
- 서버, 로그인, 저장. 모든 상태는 메모리 + 선택적으로 localStorage(설정값만).

## 2. 사도 데이터

- 후보: **114명** (이격 제외 실장 사도). 개수는 설정값.
- 기본 데이터는 플레이스홀더로 자동 생성한다. 이름은 `사도 001` 형식, 이미지는 성격 색상 원 + 번호.
- 사용자가 `saints.json`의 이름·소속·대사·이미지 경로를 직접 교체할 수 있어야 한다. **코드에 특정 IP의 캐릭터 이름이나 이미지를 넣지 않는다.**

```ts
type Personality = 'P1' | 'P2' | 'P3' | 'P4' | 'P5'; // 표시명은 rules.ts에서 설정 (예: 순수/냉정/광기/활발/우울)

interface Saint {
  id: string;              // "s001"
  name: string;            // 표시명
  title: string;           // 소속/칭호 (예: "OO 교단의 사제")
  personality: Personality;
  image?: string;          // 없으면 플레이스홀더
  lines: {
    prelimSelect: string;  // 예선 선택 화면 대사
    missionIdle: string;   // 미션 화면 대사
    finalSelect: string;   // 본선 선택 화면 대사 (예선 통과 반영)
    victory: string;       // 우승 발표 대사
  };
  // 시뮬레이션용 (§7.3) — 화면에는 기획자 시점에서만 노출
  popularity: number;      // 인기도 가중치
  fervor: number;          // 팬층 열성도 계수
}
```

## 3. 예선 규칙 (1주차)

| 규칙 | 값 | 비고 |
|---|---|---|
| 기간 | 7일 | |
| 일일 미션 | 9개 | 일일 퀘스트와 동일 조건 |
| 미션당 표 | 3표 | 하루 최대 27표, 7일 최대 189표 |
| 투표 사도 | **매일 초기화**, 하루 한 명 | 다음 날 재선택 |
| 투표 방식 | 자동 투표 | 사도를 고른 뒤 미션 보상 수령 시 즉시 귀속. 재화 소모·추가 확인 없음 |
| 이월 | 없음 | 당일 미수령 표는 소멸 |
| 중도 참여 | 잔여 기간만큼만 지급 | 미참여 기간 표는 소멸 |
| 순위·득표 | **전면 비공개** | 유저는 자신의 투표 기록과 잔여 일수만 확인 |
| 본선 진출 | 상위 **10명** 정원제 | 참여 규모 무관. 동표 시 해당 득표에 먼저 도달한 사도 우선 |
| 예선 득표 | 본선으로 이월되지 않음 | |

**미션 목록(표시용, 문구 교체 가능):**
일일 접속 1회 / 세계수 성물 자원 수령 1회 / 상점에서 아이템 구매 2회 / 왕사탕 100개 소모 / 별사탕 100개 소모 / 배틀젬 수령 1회 / 스케줄 보내기 2회 / 교단 펫 선물 수령 1회 / 일일 던전 1회 클리어

- 플레이어: 각 미션의 `이동` 버튼을 누르면 즉시 완료 상태가 된다(모의 수행). `받기` 또는 `모두 받기`로 수령하면 표가 귀속된다.
- 사도를 고르지 않은 상태에서는 `받기`가 비활성화되고 사도 선택을 유도한다.

## 5. 딜량 추상화 공식

전투 시스템은 구현하지 않고 아래 공식으로 회차 점수를 산출한다.

```
score = basePower[specTier]
      × affinity(account, bossPersonality)
      × skillFactor
      × noise           // LogNormal(μ=0, σ=0.08), 시드 기반
```

| 요소 | 정의 |
|---|---|
| `basePower` | 고스펙 1,000,000 / 중스펙 550,000 / 저스펙 200,000 (설정값) |
| `account.trainedPersonalities` | 육성된 성격 집합. 고스펙 3~5개, 중스펙 2~4개, 저스펙 1~2개 (균등 랜덤) |
| `affinity` | 보스 성격에 대응하는 파티가 육성되어 있으면 1.0, 아니면 0.55 |
| `skillFactor` | 계정별 고정값 Normal(1.0, 0.07), 0.8~1.2로 클램프 |
| 6·7일차 | 유저가 성격 선택 → 봇은 자신이 육성한 성격 중에서 선택 (구제 장치) |

- 같은 날 재도전 시 noise만 다시 굴린다. 봇의 재도전 여부는 §7 참고.
- 플레이어는 시작 시 **내 계정 설정**에서 스펙 등급과 육성 성격을 직접 고른다(기본값 중스펙, 2개).

## 7. 봇(가상 유저) 정의

### 7.1 유형 (비율·확률은 모두 패널에서 조절 가능한 **가정값**)

| 유형 | 비율 | 일일 접속률 | 미션 수행률 | 예선 행동 | 본선 행동 | 최애 예선 탈락 시 |
|---|---|---|---|---|---|---|
| `devoted` 열성 최애형 | 15% | 0.95 | 0.95 | 최애 1명에게 매일 투표 | 최애 고정, 3회 직접 도전(재도전 확률 0.6) | 이탈 0.3 / 차선 최애 0.7 |
| `light` 라이트 팬형 | 30% | 0.55 | 0.6 | 최애 위주(0.85), 가끔 다른 선호 사도 | 1회 도전 후 소탕 | 이탈 0.5 / 차선 최애 0.3 / 인기 사도 0.2 |
| `multi` 다최애 분산형 | 15% | 0.75 | 0.85 | 선호 목록 2~4명을 날마다 순환 | 생존한 선호 사도 중 1위 선호 | 이탈 0.1 / 차선 최애 0.9 |
| `optimizer` 보상 최적화형 | 10% | 0.85 | 0.9 | 최애에게 투표 | **예상 경쟁이 가장 낮은 판**을 선택(§7.4) | 영향 없음 |
| `routine` 루틴 무관심형 | 20% | 0.7 | 0.8 | 인기 상위 사도 중 랜덤(가중) | 인기 상위 사도 선택, 1회 도전 후 소탕 | 영향 없음 |
| `late` 중도 진입형 | 10% | 진입 후 0.7 | 0.7 | 예선 3~6일차 중 진입(30%는 본선 1~3일차에 첫 진입) | 라이트 팬형과 동일 | 라이트 팬형과 동일 |

- **스펙 등급은 유형과 독립**으로 부여: 고 20% / 중 50% / 저 30% (설정값).
- 미션 수행률 = 접속한 날 각 미션을 완료할 확률(미션별 독립 시행).
- 본선에서 "이탈"한 봇은 본선 전 기간 미참여 처리.
- 본선 접속일에 `devoted`는 3회 직접 도전, 나머지는 1회 도전 + 소탕 2회를 기본으로 한다.

### 7.2 선호 목록 생성
- 각 봇은 `popularity` 가중 비복원 추출로 선호 사도 3명을 순서대로 뽑는다(1번이 최애).
- `fervor`가 높은 사도를 최애로 가진 봇은 접속률·미션 수행률에 `× min(1, fervor)` 보정 대신 **상향 보정 +0.1×(fervor−1)** 를 적용한다(상한 0.98).

### 7.3 사도 인기 분포
- `popularity`: Zipf 분포, 지수 `s = 1.0` (설정값). 114명을 무작위 순서로 배정.
- `fervor`: LogNormal(0, 0.25), 0.6~1.8 클램프. **인기와 독립**이어서 "팬은 적지만 열성적인" 사도가 생긴다.

### 7.4 보상 최적화형의 판 추정
- 봇은 실제 판 규모를 모른다(비공개). 대신 **공개 인기도 인식** = `popularity × LogNormal(0, 0.3)`로 판 규모를 추정한다(커뮤니티 체감 모사).
- 본선 10명 중 `추정 판 규모 × (1 − 보상 민감도) + 선호 보너스`가 최소인 사도를 고른다. 보상 민감도 기본값 0.7.

### 7.5 순위 공개 시나리오(비교용)
- 패널에서 예선 순위를 **공개**로 바꾸면, 각 봇은 매일 투표 전 최애가 진출권(상위 10위 + 여유 5위) 밖일 경우 확률 `strategicSwitch`(기본 0.35, `devoted`는 0.1)로 진출권 안의 선호 사도 또는 인기 사도로 표를 옮긴다(사표 회피). 기획서의 "순위 비공개" 근거를 검증하기 위한 대조군.

### 7.6 규모
- 기본 10,000명(1,000~50,000 조절). 하루 진행은 Web Worker에서 계산하고 UI는 진행률 표시.

## 8. 화면 명세

전체 톤: 기획서 컬러(메인 그린 `#86A83A`, 연한 그린 `#EAF5D3`, 텍스트 `#222`), 둥근 모서리 카드, 트릭컬풍 SD 연출을 위한 이미지 슬롯. 해상도 기준 16:9 가로 화면, 최소 1280×720, 모바일은 대응하지 않아도 됨.

### 8.0 공통 레이아웃
- 상단 바: 뒤로가기, 화면 제목, 재화 표시(장식), **[유저 시점 / 기획자 시점] 토글**, 현재 일차 표시(`예선 3일차 · 5일 18시간 후 종료` 형식).
- 화면 하단 또는 우측: **`다음 날로` 버튼**. 누르면 미수령 표가 있을 경우 "미수령 표 N표는 소멸합니다" 확인 팝업 → 봇 하루 진행 → 일차 증가.
- 기획자 시점 ON일 때만 우측에 **실시간 데이터 사이드 패널**이 열린다(§8.10). 유저 시점에서는 기획서대로 순위·득표가 전혀 보이지 않아야 한다.

### 8.1 시작 화면 / 내 계정 설정 (프로토타입 전용)
- 시드 입력, 봇 수, 내 스펙 등급, 내 육성 성격(체크박스) 선택 → `이벤트 시작`.
- `빠른 실행` 버튼: 플레이어 없이 전체 14일을 즉시 시뮬레이션하고 결과 리포트로 이동.

### 8.2 이벤트 시작 연출 (기획서 p.18)
- 최초 1회만 재생, 스킵 가능.
- 시나리오: 교단이 투표로 수석 사도를 뽑는다는 공지 → 단상 위 진행자 사도의 대사 → 114명의 사도 카드가 줄지어 등장(후보군 인지).
- 대사 2~4개는 설정 파일에서 교체 가능.

### 8.3 예선 사도 선택 (p.19)
- 좌측: 선택한 사도의 큰 이미지 + 소속/이름 + `prelimSelect` 대사 말풍선.
- 우측: 114명 그리드(3열 스크롤), `필터`(성격), `정렬`(가나다/번호) 버튼.
- 하단: `투표하기` — 재화 소모 없음, 누르면 미션 화면으로 이동. 당일 이미 투표 사도를 정했으면 변경 불가 안내.

### 8.4 예선 미션 화면 (p.20)
- 좌측: 선택 사도 이미지 + `missionIdle` 대사.
- 상단 진행 현황: `금일 투표 수: n/27`, 잔여 일수, 다음 갱신까지 남은 시간(일차 기반 표시).
- 미션 리스트 9개: 아이콘, 미션명, 진행도, `투표권 ×3`, 상태 버튼(`이동`/`받기`/`완료`).
- `모두 받기`: 완료된 미션 일괄 수령 → 표 귀속 애니메이션(표가 사도 쪽으로 날아가는 연출).
- 하단 작은 영역: 나의 투표 기록(일차별 사도·표 수). 순위 정보는 없음.

### 8.5 본선 진출 공지 (p.21)
- 본선 화면 최초 진입 시 팝업. 시상식 배경 + 진출 10명 SD 카드를 일렬 배치 + 이름표.
- 예선 득표는 표시하지 않는다.
- 내가 예선에서 투표한 사도 중 진출한 사도가 있으면 작은 배지로 표시(유저 몰입 연출, 득표는 아님).

### 8.6 본선 사도 선택 (p.22)
- 예선 선택 화면과 동일 구조. 정보 영역에 `TOP 10` 장식, 대사는 `finalSelect`.
- 목록은 진출 10명만.
- 하단 경고 문구: `주의: 한 번 투표할 사도를 지정하면 본선 종료까지 변경할 수 없습니다`.
- `투표하기` → 확인 팝업 → 확정.

### 8.7 보스 침공 연출 (p.23)
- 본선 사도 확정 직후 1회 재생, 스킵 가능.
- 투표장에 거대한 보스 실루엣 등장 → 화면 흔들림·붉은 조명 → 본선 후보 사도들이 반격 태세 → "투표장을 지켜라" 문구.

### 8.8 보스전 파티 편성 (p.24)
- 좌측: 오늘의 보스 성격 표시, 내 육성 성격과 상성 여부(유리/불리), 예상 전투력.
- 투표 사도 표시 배지(항상 노출).
- 6·7일차에는 보스 성격 선택 UI(이미 고른 성격은 비활성).
- 버튼: `출발`(도전), 당일 1회 이상 도전 후에는 `소탕`(직전 기록으로 잔여 횟수 처리) 활성.
- 남은 입장 횟수 `n/3`.

### 8.9 보스전 전투 (p.25)
- 5~8초 자동 진행 연출: 파티 SD들이 공격, 데미지 숫자 팝업, 누적 딜량 카운터 상승.
- 체력바는 **보여주기용**(실제 점수와 무관), 체력바 좌측에 적 대신 **투표 사도 초상**.
- 종료 시: 이번 점수, 오늘 획득 표 `+9`, 누적 딜링 점수. 순위는 표시하지 않음.

### 8.10 기획자 시점 사이드 패널 (토글 ON일 때)
- 예선: 사도별 누적 득표 상위 20 막대그래프, 현재 진출권 컷라인, 오늘 참여 봇 수/유형별 참여율.
- 본선: 사도별 랭킹판 참여자 수, 사도 득표, **내 실제 딜링 순위와 현재 보상 구간**, 유형별 이탈률.
- "유저 시점에서는 보이지 않는 정보"라는 라벨을 상단에 고정.

### 8.11 결과 발표 (p.26)
- 본선 7일차 종료 후 메인 진입 시 팝업: `제 1회 교단 수석 사도` + 우승 사도 + 왕관 + `victory` 대사.
- 이어서 나의 딜링 순위 보상 카드(구간, 이름표 배경·테두리, 재화), 사도 순위 보상 목록(1위/2~3위/4~10위).
- `투표 총 결과 보기` → 개발자 노트 형식 페이지: 예선 114명 전체 득표 순위, 본선 10명 득표.

### 8.12 검증 리포트 (프로토타입 전용)
- §9 지표를 차트·표로 표시. 각 지표 옆에 연결된 기획 의도 문장과 판정(통과/주의/실패).
- `시나리오 비교`(§10)로 이동하는 버튼.

## 9. 검증 지표

### H1. 보상이 사도 선택을 왜곡하지 않는가
> 기획 의도: "재화를 기준으로 응원 사도를 고르는 일이 없어야 인기투표가 성립"

| 지표 | 계산 |
|---|---|
| 판별 참여자 수 | 본선 사도별 랭킹판 참여 봇 수 |
| **선택별 기대 보상 격차** | 동일 계정(스펙·성격·skill 고정)을 10개 판 각각에 넣었다고 가정하고 최종 점수로 각 판에서의 구간을 계산 → 판별 보상 가치(§6.2 환산) 최대−최소. 스펙 등급별로 산출 |
| 명예 보상 접근성 | 판별 "상위권 이상(100위 이내)" 진입에 필요한 최소 점수 |
| 최적화형 성과 | `optimizer`와 같은 스펙의 비최적화 봇의 평균 보상 가치 비교 |

판정 기준(기본): 같은 스펙의 기대 보상 격차가 참가상 대비 +20% 이상이면 `주의`, 명예 보상 구간이 2단계 이상 바뀌면 `실패`.

### H2. 동일 투표력이 선호를 측정하는가
| 지표 | 계산 |
|---|---|
| 팬 수 vs 득표 상관 | 사도별 최애 봇 수와 예선 득표의 스피어만 상관 |
| 열성 효과 | 팬 수 순위와 득표 순위가 뒤바뀐 사도 쌍의 비율, `fervor`와 순위 역전의 관계 |
| 진출자 일치도 | 팬 수 기준 상위 10명과 실제 진출 10명의 교집합 수 |
| 재선택 효과 | 예선 재선택을 "고정"으로 바꾼 시나리오와 진출자 비교 |

### H3. 예선 탈락 유저가 본선에 남는가
| 지표 | 계산 |
|---|---|
| 최애 탈락 비율 | 최애가 본선에 진출하지 못한 봇 비율(유형별) |
| 본선 이탈률 | 예선 참여 봇 중 본선 미참여 비율(유형별) |
| 판 밀도 | 판별 참여자 수의 최소/중앙값/최대, 참여자 100명 미만 판 개수 |
| 진출 인원 민감도 | 진출 인원 5/10/15/20에서 위 지표 비교 |

### 보조 지표
- 일차별 참여율(이월 없음 효과), 중도 진입 봇의 획득 표 비율, 사도 득표 지니계수.

## 10. 기획자 패널 / 시나리오 비교

### 조절 가능한 값
- 규칙: 진출 인원, 미션 수, 미션당 표, 본선 입장 횟수, 입장당 표, 예선 재선택(매일/고정), 예선 순위 공개(비공개/공개), **딜링 판 방식**(사도별 / 통합 / 사도별+백분위 구간)
- 보상: §6.2 테이블 전체, 보상 가치 환산값
- 유저: 유형 비율, 유형별 확률값, 스펙 분포, 보상 민감도, `strategicSwitch`
- 사도: Zipf 지수, fervor 분산
- 실행: 봇 수, 시드, 반복 횟수

### 시나리오 비교
- 시나리오 A/B(최대 4개)를 저장하고 각각 N개 시드(기본 20)로 반복 실행.
- 지표별 평균 ± 표준편차를 나란히 표시하고 차트로 비교.
- 설정은 JSON으로 내보내기/불러오기.
- 기본 프리셋: `기획서 원안`, `통합 랭킹판`, `순위 공개`, `진출 20명`.

| # | 항목 | 확정 내용 |
|---|---|---|
| B1 | "먼저 도달" 동표 처리 | 시각 = (일차, 그날 시드 셔플로 정한 유저 처리 순번, 회차). 사도·유저가 **최종 득표/점수에 마지막으로 도달한 시각**이 빠른 쪽이 우선 |
| B2 | 1~5일차 보스 성격 순서 | `rules.ts`의 성격 순서(P1→P5) 고정, 설정으로 변경 가능 |

| B4 | devoted 본선 도전 | 1회차 직접 도전, 2·3회차는 각각 0.6 확률로 직접 재도전, 아니면 소탕. 3회 입장은 항상 소진 |
| B5 | optimizer 판 선택 | `비용 = 정규화 판 규모 × 민감도 − 선호 보너스 × (1 − 민감도)` 최소 사도 선택. 정규화 판 규모 = 인식 인기도 ÷ 진출자 중 최대값. 선호 보너스 1순위 1.0 / 2순위 0.6 / 3순위 0.3 / 그 외 0 (가정값). 민감도가 높을수록 보상 우선 |
